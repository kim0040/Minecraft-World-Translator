# UI/UX 실사용 점검·개선 — 2026-10-02

사용자 실사용 피드백("디자인 의도는 좋으나 사용 경험이 나쁘다")에 따라 browser fixture로 새 설치·재방문·좁은 창 흐름을 직접 따라가며 점검하고 고쳤다. UI-only 변경이며 Python/Rust/sidecar는 바꾸지 않았다. Phase 상태는 바뀌지 않는다.

## 발견한 문제와 조치

| 문제 | 영향 | 조치 |
| --- | --- | --- |
| 환경 설정에서 저장하지 않은 변경(입력한 API 키 포함)이 사이드바·메뉴·월드 칩·드롭으로 이동하면 경고 없이 사라짐 | 키를 입력하고 다른 화면을 누르면 처음부터 다시 입력 | `AppState.leave()`가 모든 페이지 이동을 막고 "저장하고 이동 / 저장하지 않고 이동 / 계속 편집"을 묻는다 |
| 새 설치에서 모델·키가 없다는 사실을 4단계(번역 진행)에서야 알림 | 스캔·검토를 마친 뒤 막힘 | 월드·스캔 화면에 비차단 안내, 번역 진행 화면에는 빠진 항목을 한 번에 나열하는 차단 안내 하나(`SetupNotice`) |

| "번역 언어 및 문체" 부제가 입력 placeholder 문구 | 의미 없는 부제 | 전용 부제 문구 |
| 접힌 설정 섹션 카드 아래 빈 공간 | 카드 높이가 들쭉날쭉 | 닫힌 `details`의 row-gap 제거 |
| "지원 정보 새로고침" 버튼이 실제로는 모델 목록 조회 | 처음 쓰는 사람이 모델을 고를 방법을 못 찾음 | "모델 목록 불러오기"와 관련 오류 문구 정리 |
| 스캔 시작 카드가 페이지 lead 문구를 반복 | 정보 없음 | 소요 시간·취소 가능 안내 |

| 작업 중 다른 화면에서 진행 화면으로 돌아갈 단서 없음, 접힌 rail 상태 점은 작업 중에도 초록 | 진행 상황을 찾기 어려움 | 사이드바 "작업 화면 보기" 버튼, rail 점이 작업 중 강조색으로 깜빡임 |
| 월드가 선택된 상태의 버튼도 "월드 폴더 열기" | 다른 월드로 바꾸는 버튼인지 모호 | "다른 월드 열기" |

## 검증

- `pnpm check` 0 errors / 0 warnings, `pnpm test:frontend` PASS(i18n catalog 포함).
- Browser(Linux, Playwright chromium-1194, 로컬 executablePath override): settings-ux/layout/workflow/screens/help-and-maintenance/theme/native/motion/startup 첫 실행 109 PASS/5 FAIL. 실패 5개는 "설정에서 나가면 draft가 조용히 버려진다"는 이전 동작과 바뀐 문구를 전제로 한 테스트였고, 이동 확인에서 "저장하지 않고 이동"을 고르도록·문구를 갱신한 뒤 workflow/settings-ux/ux-flow 46+1 PASS. 새 `tests/browser/ux-flow.spec.ts` 5 PASS(새 설치 안내→설정→돌아가기, 이동 확인 3가지 선택+axe, 좁은 창 키보드, toast 위치).
- fixture에 `fresh=1`(모델·키 없는 새 설치) 시나리오를 추가했다.
- 실행하지 않음: Python/Rust 전체, native(macOS/Windows) 창, 실제 provider. native 창 닫기(⌘Q/창 X) 시 저장하지 않은 설정 경고는 구현하지 않았다(작업 중 종료 보호만 기존대로).

## 후속 수정 — U3·U4·U6

같은 날 [알려진 UI/UX 문제](../ux-issues.md)의 중간 항목 중 웹에서 바로 고칠 수 있는 세 건을 고쳤다. UI-only이며 Python/Rust/sidecar는 바꾸지 않았다.

| 항목 | 조치 |
| --- | --- |
| U3 시작 실패 시 도움말 접근 불가 | 사이드바 도움말·정보는 시작 실패에도 열린다(나머지는 계속 비활성). 실패 안내에 "도움말 보기"를 두고, 도움말·정보 화면 위에도 같은 실패 안내와 다시 시도를 유지한다. 메뉴 막대의 도움말·단축키·라이선스·문제 보고도 동작한다. 시작 실패 동안 상태 점은 위험색이며, 설정으로 이어지는 둘러보기 버튼은 숨긴다. |
| U4 복원 후 조용한 초기화 | 복원 직후 백업 관리 화면에 "번역하려면 다시 스캔하세요" 안내와 "월드 스캔으로" 버튼을, 스캔 화면에 같은 안내를 둔다. `lastRestoreId`는 `resetJob()`에서 지우고 복원 직후에만 다시 설정하므로 새 스캔·월드 변경·스캔 범위 변경 때 사라진다. |
| U6 좁은 창 상세 모달 | 창 폭 1100px 대신 목록 영역 폭을 ResizeObserver로 재고 다음 frame에 적용한다. 680px 이상이면 옆 패널(940px 미만은 280px, 이상은 340px), 미만이면 시트. 1024·840px 창에서도 옆 패널이다. 패널에서 편집 중 좁아지면 시트가 열리고 초안·focus가 이어지며, 편집 중이 아니면 시트를 띄우지 않는다. |

점검 중 함께 고친 것:

- 후보 검토의 "번역 대상으로 선택된 문장이 없습니다" 경고(`role=alert`)가 창 폭 1100px 미만에서 일괄 선택 안내와 같은 `.hint` 규칙에 걸려 숨겨졌다(main에도 있던 문제). 버튼만 비활성이고 이유가 보이지 않았다. 숨김을 일괄 선택 안내에만 적용했다.
- 시작 실패 상태의 진단 정보 복사가 기본 설정의 제공사를 사용자 제공사처럼 적었다. 시작 실패 때는 `Startup: failed`로 적는다.

검증: `pnpm check` 0 errors/0 warnings, `pnpm test:frontend` 62 PASS, browser 전체 123 PASS(macOS, Playwright chrome, workers 1). 이 브랜치의 첫 전체 browser PASS다. 새 테스트: 시작 실패 후 도움말·정보·다시 시도(+axe), 1024/840px 옆 패널, 복원 후 안내→스캔 이동→새 스캔 시 사라짐(+axe), 1024px에서 포함 문장 없음 경고 표시. 기존 테스트 중 1024px에서 시트를 기대하던 키보드 테스트는 720px로, 840px에서 시트를 기대하던 초안 resize 테스트는 700px로 옮겼다. Python/Rust·native는 실행하지 않았다(Rust·Python 변경 없음).

## 화면 점검 후속 — 같은 날

기본 창(1180×800)과 최소 창(840×620)에서 새 설치→스캔→검토→진행→결과(성공·일부·실패·취소·재시도)→백업→설정·도움말을 다시 따라가며 찾은 문제 중 화면 코드·문구로 고칠 수 있는 것을 고쳤다. UI·문구·문서만 바꿨고 Python/Rust/sidecar는 바꾸지 않았다.

| 문제 | 조치 |
| --- | --- |
| 창 높이 650px 이하(최소 창 840×620, 1180×640 등)에서 후보 검토의 "번역 진행 단계로 이동" 버튼이 화면 아래로 밀려 스크롤해야 보임 | 이 높이에서는 하단 막대를 작업 영역 아래에 고정 |
| 추론 안내가 이름이 바뀐 버튼("지원 정보 새로고침")을 가리킴 | ko/en/ja 문구와 4개 언어 사용 안내를 "모델 목록 불러오기"로 |
| 추론을 지원하지 않는 모델인데 실행 화면에 "추론 설정 수정" 버튼 | 모델 정보로 미지원이 확인되면 버튼을 숨김(정보를 모르면 유지) |
| 저장된 작업이 있으면 "이어서 번역"만 있고 새로 번역할 방법이 없음 | "처음부터 다시 번역" 보조 버튼과 비용 재발생 확인 dialog(`translate.start`, 코어가 체크포인트를 지움). 실패하면 이어서 할 기록을 코어에 다시 묻는다 |
| 같은 단계를 "번역 진행"·"번역 준비 단계로 이동"·"번역 준비 및 실행"으로 부름 | 단계 표시 이름으로 통일(ko/en/ja) |
| 이어서 할 작업 안내의 제목과 본문 첫 문장이 같은 말 | 본문에서 반복 문장 제거 |
| 실패 목록이 최대 20개만 오는데 화면은 개수를 말하지 않음 | 실패 수가 목록보다 많으면 "실패한 N개 중 M개만 보여 줍니다" |
| "실패" 결과가 변경 파일 0개인데도 "필요하면 백업을 복원" 안내 | 변경 파일이 없으면 "월드 파일은 바뀌지 않았습니다" |
| 성공 결과에 다음 행동 안내가 없음 | "Minecraft에서 월드를 열어 확인, 마음에 들지 않으면 백업 관리에서 되돌리기" |
| 작업 중 백업 화면의 복원 버튼이 이유 없이 비활성 | 작업 중에는 복원할 수 없다는 안내 |
| 도움말 빠른 시작 카드가 1180px 창에서 3+1로 나뉨 | 2×2, 넓은 창에서 4열 |

검증: `pnpm check` 0 errors/0 warnings, `pnpm test:frontend` PASS, browser 전체 PASS(아래 커밋 직전 실행, macOS Playwright chrome). 새 테스트: 낮은 창 두 크기의 다음 단계 버튼, 추론 미지원 모델의 수정 버튼 숨김, 처음부터 다시 번역(취소·확인·`translate.start`·axe), 실패 목록 개수, 성공 다음 행동, 작업 중 백업 안내. 실행 단계 이름 변경으로 기존 테스트의 버튼·제목 이름을 갱신했고, 추론 설정 이동 테스트는 추론 지원 모델 fixture로 바꿨다. Python/Rust·native·실제 provider는 실행하지 않았다.

남긴 것: 실패 이유의 제공사 원문(U16, Python), 실패 뒤 다시 시도 경로의 실제 확인(U17), 좁은 단계 표시(U18), Comet 키 발급 링크(U19).
